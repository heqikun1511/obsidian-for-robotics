# 硬件设计与 STM32 核心模块笔记

## 一、 PCB 布线设计规范

在 PCB 设计阶段，为了保证电路的稳定性和抗干扰能力，需遵循以下原则：

- **走线原则**：走线尽量短一点，减少寄生电感。
- **电源铺铜**：电源部分尽量铺铜，保证电流承载能力。
- **隔离与禁止区域**：不要在电感下方走线，设置禁止区域。
- **DCDC 布局**：DCDC（开关电源）需保持地平面完整。
- **散热处理**：先铺铜，再打散热孔（过孔）。
- **总线终端电阻**：CAN 和 CANH 之间要有一个 **120Ω** 的电阻（用于阻抗匹配，消除信号反射）。
- **晶振选型**：单片机外部一般外接无源晶振，辅助 RTC（实时时钟）。

## 二、 STM32 时钟系统（HSE 与 LSE）

STM32 的时钟源主要分为高速和低速两类，分别承担不同的系统任务：

### 1. 高速晶振 (HSE - High Speed External)
- **角色**：系统的“**主引擎**”。
- **频率**：通常为 **8MHz** 或 **25MHz**。
- **作用**：它为主芯片和所有高速外设（如 USB、SPI 通信）提供核心时钟。
- **重要性**：是让程序高速运行的基础，**不可或缺失**。

### 2. 低速晶振 (LSE - Low Speed External)
- **角色**：精准的“**计时器**”。
- **频率**：经典的 **32.768kHz**。
- **原理**：这个频率因为可以被 2 的 15 次方整除，能极其准确地分频出 **1秒** 的计时信号。
- **核心任务**：驱动实时时钟 (**RTC**) 模块。确保系统在掉电或深度休眠时，依然能靠纽扣电池精准走时。
- **设计优势**：由于频率低、功耗极低，是低功耗设计的关键。

---

## 三、 电源管理：VCAP 引脚的作用

### 1. 什么是 VCAP？
- **背景**：STM32F407 的核心（CPU、SRAM、数字外设）需要工作在 **1.2V** 左右，而不是外部输入的 3.3V。
- **定义**：这个降压和稳压的工作由芯片内部的**嵌入式线性调压器**完成。而 **VCAP 引脚**就是连接这个调压器外部滤波电容的**专用引脚**。

### 2. 为什么需要接电容？不接会怎样？
- **原因**：调压器输出的 1.2V 电压必须非常稳定，否则核心会工作异常甚至死机。
- **要求**：必须**在 VCAP 引脚和地（VSS）之间，紧挨着引脚焊接一个 2.2μF 的陶瓷电容**。
- **作用**：用于滤除电压纹波，保证供电质量（提供稳定的 1.2V 核心电压）。

# 复位监控 + 看门狗电路笔记 (U57: TPS3823-33DBVR)
## 一、 核心概述
- **核心芯片**：U57 (型号：TPS3823-33DBVR)
- **芯片类型**：TI 的电源监控器 / 复位监控器 / 看门狗定时器 (Reset Supervisor / Watchdog Timer)
- **应用场景**：用于保护 ESP32-P4 / MCU 系统。
**主要防护目的：**
1. 3.3V 电源异常
2. 程序跑飞
3. 上电复位不稳定
4. 需要手动复位的情况
## 二、 U57 是什么？
TPS3823-33 是一款高度集成的电源管理芯片，主要包含两个核心功能：
1. **监控 3.3V 电源是否正常**（电压监控）
2. **监控 MCU 是否定期喂狗**（看门狗定时器）
**工作逻辑**：
如果电源异常，或者 MCU 没有按时喂狗，芯片会将 `RESET#` 引脚拉低，强制让 MCU 复位。
## 三、 各个引脚的作用
以下是 U57 芯片（TPS3823 封装）的引脚功能定义表：
| 引脚 | 名称 | 作用 |
| :--- | :--- | :--- |
| **1** | `RESET#` | 低有效复位输出，接 MCU 的 `NRST` 引脚 |
| **2** | `GND` | 地 |
| **3** | `MR#` | Manual Reset，手动复位输入，低有效 |

### 1. 防范“假死”与时钟失效（最致命的差异）

- **内部看门狗**：它依赖单片机内部的时钟源（如内部的 RC 振荡器）来计时。如果单片机内部的主时钟（PLL）或内部 RC 振荡器因为电压不稳、强电磁干扰（比如电机启动、继电器吸合）而**停振或跑偏**，内部看门狗可能跟着一起失效，无法触发复位。
    
- **外部看门狗**：它是一个**完全独立的物理芯片**，拥有自己独立的时钟和电源。不管单片机内部变成什么样（时钟停了、死锁了、电源被拉低了），外部看门狗依然在按自己的节奏计时。只要单片机没能按时“喂狗”，它就会强制拉低 `RESET#` 引脚，把单片机强行拽回正轨。
    

### 2. 防范“程序陷入死循环但仍在喂狗”

- 如果程序跑飞，正好飞进了一段包含“喂狗指令”的死循环里（虽然概率低，但在复杂系统中会发生），内部看门狗就会被一直喂，永远不会复位。
    
- 外部看门狗可以配合“窗口看门狗（Window Watchdog）”的概念使用，或者将喂狗动作放在主循环的特定任务中。如果某个关键任务卡死，即使其他中断还在跑，外部看门狗也能检测到异常并复位。
    

### 3. 应对单片机“彻底死锁”（硬件级死机）

- 有时候单片机会因为 ESD（静电）、过压、欠压等原因进入**硬件级死锁（Latch-up）**。此时 CPU 完全停摆，连内部看门狗的中断都响应不了。
    
- 外部看门狗是**硬件电路**，不受单片机内部状态影响。它能提供最底层的物理级“硬复位”，这是内部看门狗做不到的。
