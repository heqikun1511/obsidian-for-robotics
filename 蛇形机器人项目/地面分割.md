## 为什么需要地面分割？

激光雷达/深度相机扫到的点云里，**地面点通常占 40%~70%**：

text

       相机/雷达
          │
          ▼
    ┌───────────┐
    │ · · · · · │  ← 墙（障碍物）
    │ · · · · · │
    │ · · · · · │
    └───────────┘
   ／／／／／／／／／／／  ← 地面（大量点）

如果不分割：

| 问题       | 后果               |
| -------- | ---------------- |
| 地面点被当成障碍 | 机器人"看到"满地点云，无法前进 |
| 计算浪费     | 大量地面点参与聚类、栅格化    |
| 代价地图全被占满 | 规划器找不到可行路径       |
| 扇区分析失效   | 前方地面被误判为"近处障碍"   |

**所以：地面分割是障碍物检测的前置必要步骤。**

# 代码详解



## 一、整体结构

cpp

pcl::SACSegmentation<pcl::PointXYZ> segmenter;   // 1. 创建分割器
segmenter.setOptimizeCoefficients(true);         // 2. 优化系数
segmenter.setMethodType(pcl::SAC_RANSAC);        // 3. 用 RANSAC
segmenter.setMaxIterations(120);                 // 4. 最多迭代 120 次
segmenter.setDistanceThreshold(ground_distance_threshold_m_);  // 5. 距离阈值
if (constrain_ground_normal_) {
    // 6a. 约束法向量朝上的平面
    segmenter.setModelType(pcl::SACMODEL_PERPENDICULAR_PLANE);
    segmenter.setAxis(Eigen::Vector3f(0.0F, 0.0F, 1.0F));
    segmenter.setEpsAngle(static_cast<float>(ground_max_tilt_deg_ * kPi / 180.0));
} else {
    // 6b. 不约束，任意平面
    segmenter.setModelType(pcl::SACMODEL_PLANE);
}

**目的**：找到地面平面，输出内点（地面点）和平面系数。


## 二、逐行解析

### 1. `pcl::SACSegmentation<pcl::PointXYZ> segmenter;`

- `SACSegmentation` = **SAmple Consensus Segmentation**，PCL 的模型拟合分割器
    
- `<pcl::PointXYZ>`：处理的点类型（只含 x, y, z）
    
- 后面会调用 `segmenter.segment(inliers, coefficients)` 得到结果
    

### 2. `segmenter.setOptimizeCoefficients(true);`

- 拟合出平面后，**用内点重新优化平面系数**
    
- `true`：用所有内点做最小二乘精修（结果更准）
    
- `false`：直接用 RANSAC 随机采样的三点（可能有噪声）
    

**建议**：一般设 `true`，精度更好，代价很小。

### 3. `segmenter.setMethodType(pcl::SAC_RANSAC);`

- 选择 **RANSAC** 作为采样一致性方法
    
- 其他选项：
    
    - `SAC_LMEDS`：最小中值
        
    - `SAC_MSAC`：M-estimator
        
    - `SAC_RRANSAC`：随机 RANSAC
        
    - `SAC_RMSAC`：随机 MSAC
        

**RANSAC 是最常用、最平衡的选择**。

### 4. `segmenter.setMaxIterations(120);`

- 最多迭代 **120 次**
    
- 每次随机采样一个模型，统计内点
    
- 迭代越多，找到最优平面的概率越高，但耗时越长
    

**取值建议**：

|点云点数|推荐迭代|
|---|---|
|几千|50~100|
|几万|100~500|
|几十万|500~1000|

**120 次**对一般的点云够用（这是 `CloudSafetyNode` 的默认值）。
### `segmenter.setDistanceThreshold(ground_distance_threshold_m_);`

- **点到平面的距离阈值**，3.5cm（默认）
    
- 距离 < 阈值 → 内点（地面）
    
- 距离 ≥ 阈值 → 外点（障碍物）
    

**这是最关键的参数**：

|阈值|效果|
|---|---|
|太小（如 1cm）|地面点漏检，地面被当成障碍物|
|太大（如 10cm）|障碍物底部被误判为地面|

对应参数：`ground_distance_threshold_m_`（默认 0.035）


## RANSAC 完整流程

text

输入点云
   │
   ▼
┌─────────────────────────────┐
│ 迭代 120 次（maxIterations）  │
│                             │
│  1. 随机选 3 个点             │
│  2. 确定一个平面              │
│  3. 检查法向量约束（可选）     │
│     - 不满足 → 跳过           │
│     - 满足 → 继续             │
│  4. 统计内点（距离 < 阈值）    │
│  5. 记录内点最多的平面         │
└─────────────────────────────┘
   │
   ▼
最优平面
   │
   ▼
用内点重新优化系数（setOptimizeCoefficients）
   │
   ▼
输出：内点索引 + 平面系数 (a, b, c, d)
