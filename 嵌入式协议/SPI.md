

# SPI 通信详细笔记

## 一、SPI 是什么

**SPI（Serial Peripheral Interface，串行外设接口）** 是一种**同步、全双工、高速**的串行通信协议，由 Motorola 提出，广泛用于芯片间短距离通信（传感器、Flash、显示屏、MCU 之间）。

### 核心特点

| 特点 | 说明 |
|------|------|
| **同步** | 有独立的时钟线（SCK），靠时钟同步 |
| **全双工** | 同时收发（MOSI 发、MISO 收） |
| **主从架构** | 一个 Master，一个或多个 Slave |
| **高速** | 常见几 MHz ~ 几十 MHz，可达上百 MHz |
| **短距离** | 板级/芯片间，不适合长距离 |
| **无寻址** | 用片选线（CS/SS）选从机，不是地址 |
| **无应答** | 没有 ACK/NACK 机制（不像 I2C） |

### 与 I2C、UART 对比

| 特性 | SPI | I2C | UART |
|------|-----|-----|------|
| 线数 | 4（+每从机 1 CS） | 2 | 2 |
| 双工 | 全双工 | 半双工 | 全双工 |
| 速度 | 高 | 中 | 中 |
| 多从机 | 每从机一根 CS | 地址寻址 | 点对点 |
| 时钟 | 有 | 有 | 无（异步） |
| 应答 | 无 | 有 ACK | 无 |
| 距离 | 短 | 短 | 较长 |

## 二、四根信号线

| 线名 | 全称 | 方向 | 作用 |
|------|------|------|------|
| **SCK** | Serial Clock | Master → Slave | 时钟，同步数据 |
| **MOSI** | Master Out Slave In | Master → Slave | 主发从收 |
| **MISO** | Master In Slave Out | Slave → Master | 从发主收 |
| **CS/SS** | Chip Select / Slave Select | Master → Slave | 片选，低电平有效（通常） |

## 三、四种 SPI 模式（CPOL / CPHA）
SPI 有 4 种模式，由两个参数决定：
| 参数 | 含义 |
|------|------|
| **CPOL** | Clock Polarity，时钟极性（空闲时 SCK 是高还是低） |
| **CPHA** | Clock Phase，时钟相位（数据在哪个边沿采样） |
### 四种模式
| 模式 | CPOL | CPHA | 空闲 SCK | 采样边沿 | 移出边沿 |
|------|------|------|---------|---------|---------|
| **Mode 0** | 0 | 0 | 低 | 上升沿 | 下降沿 |
| **Mode 1** | 0 | 1 | 低 | 下降沿 | 上升沿 |
| **Mode 2** | 1 | 0 | 高 | 下降沿 | 上升沿 |
| **Mode 3** | 1 | 1 | 高 | 上升沿 | 下降沿 |
**最常用**：Mode 0 和 Mode 3。
### 图示（Mode 0）

MOSI ──D7───D6───D5───D4──...  
↑ ↑

**关键**：Master 和 Slave 必须**用相同模式**，否则数据错乱。

## 四、数据传输过程
### 基本流程

1. Master 拉低目标从机的 CS
    
2. Master 产生时钟 SCK
    
3. 每个时钟周期，MOSI 和 MISO 同时移出/移入 1 bit
    
4. 传输完 N bit 后，Master 拉高 CS
    

text

### 全双工的"交换"本质
SPI 本质是**移位寄存器交换**：

Master 移位寄存器 Slave 移位寄存器  
[D7 D6 D5 D4 D3 D2 D1 D0] [Q7 Q6 Q5 Q4 Q3 Q2 Q1 Q0]  
│ │  
└────── 循环移位 ──────────────┘  
8 个时钟后：  
Master 收到 [Q7..Q0]  
Slave 收到 [D7..D0]

text

**每来一个时钟，双方各移出 1 bit、移入 1 bit**——所以 SPI **"发"的同时也在"收"**。
**重要推论**：
- **想收数据，也必须发数据**（发 dummy 字节，如 `0xFF` 或 `0x00`）
- **想发数据，也会收到数据**（收到的是从机的响应）

## 五、蛇形机器人 SPI 通信实例
### 常量定义
```cpp
namespace snake_spi {
constexpr uint8_t kMagic0 = 0x53U;          // 'S'
constexpr uint8_t kMagic1 = 0x52U;          // 'R'
constexpr uint8_t kJointCount = 8U;         // 8 个关节
constexpr uint8_t kFrameSize = 32U;         // 帧长 32 字节
constexpr uint32_t kCommandTimeoutMs = 150U; // 命令超时 150ms

|常量|值|含义|
|---|---|---|
|`kMagic0`|`0x53`|帧头魔数 1（ASCII `'S'`）|
|`kMagic1`|`0x52`|帧头魔数 2（ASCII `'R'`）|
|`kJointCount`|8|8 个关节|
|`kFrameSize`|32|帧长 32 字节|
|`kCommandTimeoutMs`|150|命令超时 150ms|

### 遥测页枚举

cpp

enum class TelemetryPage : uint8_t {
    Joints = 0,        // 关节状态
    Imu = 1,           // IMU 数据
    ServoCurrent = 2   // 舵机电流
};

**用途**：主控通过页号选择要读取的遥测数据，分页传输节省带宽。

### 协议设计要点

|设计|目的|
|---|---|
|**魔数 `0x53 0x52`**|帧同步、校验，防止误解析|
|**固定帧长 32 字节**|定长帧，解析简单|
|**页号分页**|数据多，分页传，省带宽|
|**超时 150ms**|通信看门狗，超时触发安全停止|

### 典型帧结构（推测）

请求帧：
[0]     kMagic0 (0x53)

[0]     kMagic0 (0x53)
[1]     kMagic1 (0x52)
[2]     TelemetryPage（回显页号）
[3..34] 数据载荷
[35..]  校验（CRC/checksum）

## 六、SPI 编程要点

### 1. 初始化配置

cpp

// 伪代码：配置 SPI
spi_config.mode = SPI_MODE_0;         // CPOL=0, CPHA=0
spi_config.speed = 10'000'000;        // 10 MHz
spi_config.bit_order = MSB_FIRST;     // 高位先发
spi_config.data_size = 8;             // 8 bit/字

**配置项**：

|项|说明|
|---|---|
|**模式**|CPOL/CPHA（Mode 0~3）|
|**时钟频率**|不能超过从机最大频率|
|**位序**|MSB first 或 LSB first|
|**数据位宽**|通常 8 bit|
|**CS 控制**|硬件自动或软件手动|

### 2. 收发数据

cpp

// 全双工：发 1 字节，同时收 1 字节
uint8_t tx = 0xAB;
uint8_t rx;
spi_transfer(&tx, &rx, 1);
// 只收：发 dummy
uint8_t dummy = 0xFF;
spi_transfer(&dummy, &rx, 1);
// 多发/多收
uint8_t tx_buf[N], rx_buf[N];
spi_transfer(tx_buf, rx_buf, N);

### 3. CS 控制

cpp

// 硬件 CS（推荐）
spi_set_cs(device_id);        // 自动拉低/拉高
// 软件 CS（手动）
gpio_set_low(cs_pin);
spi_transfer(...);
gpio_set_high(cs_pin);

## 七、SPI 常见问题与调试

|问题|原因|解决|
|---|---|---|
|**收不到数据**|模式不匹配|检查 CPOL/CPHA|
|**数据错位**|位序错（MSB/LSB）|检查 bit order|
|**数据全 0/全 FF**|MISO 没接/从机没响应|检查接线、CS|
|**偶尔错**|时钟太快|降低频率|
|**多从机干扰**|CS 没拉高|确保空闲时 CS 高|
|**数据不稳**|线太长、无屏蔽|缩短线、加屏蔽|
|**模式对但错位**|时钟极性/相位不匹配|逐一试 4 种模式|

### 调试步骤

text

1. 示波器/逻辑分析仪看 SCK、MOSI、MISO、CS 波形
2. 确认模式（CPOL/CPHA）匹配
3. 确认时钟频率不超限
4. 确认 CS 时序正确（传输前拉低、后拉高）
5. 确认位序（MSB/LSB）
6. 确认字节序（大端/小端）

## 八、SPI 优缺点

### 优点

|优点|说明|
|---|---|
|**高速**|比 I2C/UART 快得多|
|**全双工**|同时收发|
|**简单**|无地址、无仲裁、无 ACK|
|**灵活**|支持任意位宽、任意协议|

### 缺点

|缺点|说明|
|---|---|
|**线多**|每个从机一根 CS，多从机时线多|
|**无应答**|没有 ACK，无法确认收到|
|**无寻址**|靠 CS 选从机，不能广播|
|**距离短**|只适合板级|
|**无标准协议**|数据格式由设备自定义（如魔数、页号）|

## 十、协议设计建议（自定义 SPI 协议）

设计自定义 SPI 协议时考虑：

|要素|建议|
|---|---|
|**帧头**|用魔数（如 `0x53 0x52`）同步|
|**长度**|定长简单，变长灵活（需长度字段）|
|**命令/页号**|用枚举区分功能|
|**校验**|CRC16/CRC32 或简单 checksum|
|**超时**|通信看门狗，超时安全停止|
|**字节序**|明确大端/小端|
|**版本**|预留版本字段，便于升级|

## 十二、一句话总结

**SPI 是一种同步、全双工、高速的板级串行通信协议：Master 通过 SCK 提供时钟、CS 选择从机，在 MOSI/MISO 上同时收发数据。它有 4 种模式（CPOL/CPHA），本质是移位寄存器交换——发的同时必收。蛇形机器人用它做主控与关节控制器之间的通信，通过魔数同步、分页传输遥测、超时保护，实现高效可靠的内部数据交换。**
