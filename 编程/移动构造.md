### 移动构造怎么工作

cpp

class Buffer {
public:
    Buffer(std::size_t size) : data_(new int[size]), size_(size) {}
    // 拷贝构造：分配新内存，复制数据
    Buffer(const Buffer& other)
        : data_(new int[other.size_]), size_(other.size_) {
        std::copy(other.data_, other.data_ + size_, data_);
    }
    // 移动构造：偷走对方的指针，不分配、不复制
    Buffer(Buffer&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;   // 关键：让对方不再持有资源
        other.size_ = 0;
    }
    ~Buffer() { delete[] data_; }
private:
    int* data_;
    std::size_t size_;
};

移动构造做的事：

1. **直接把 `other` 的指针拿过来**（`data_ = other.data_`）
    
2. **把 `other` 的指针置空**（`other.data_ = nullptr`）
    

这样：

- **没有新内存分配**
    
- **没有数据复制**
    
- `other` 变成「空壳」，析构时 `delete[] nullptr` 是安全的
    
- 资源所有权从 `other` 转移到了新对象
    

**复杂度从 O(n) 降到 O(1)。**

### 关键点：`Buffer&&` 是什么

cpp

Buffer(Buffer&& other)
//     ^^^^^^^^ 右值引用

`Buffer&&` 是**右值引用**，只能绑定到**右值**（临时对象、即将销毁的对象）。这是移动构造和拷贝构造的区分标志：

|构造函数|参数|绑定对象|
|---|---|---|
|拷贝构造|`const Buffer&`|左值（有名字的变量）|
|移动构造|`Buffer&&`|右值（临时对象、`std::move` 的结果）|

### 什么时候调用移动构造

**1. 从函数返回对象**

cpp

Buffer createBuffer() {
    Buffer b(1000000);
    return b;   // 优先移动，而不是拷贝
}
Buffer a = createBuffer();   // 移动构造

**2. 用 `std::move` 显式转移**

cpp

Buffer a(1000000);
Buffer b(std::move(a));   // 移动构造，a 之后变成空壳

`std::move` 本身不移动任何东西，它只是**把左值转成右值引用**，告诉编译器「这个对象可以被移动」。

**3. 临时对象直接构造**

cpp

Buffer a(Buffer(1000000));   // 移动构造（或直接省略，见下文）

### 移动构造 vs 拷贝构造

|对比项|拷贝构造|移动构造|
|---|---|---|
|参数|`const T&`|`T&&`|
|绑定|左值|右值|
|行为|分配新资源，复制内容|转移资源所有权|
|代价|通常 O(n)|通常 O(1)|
|源对象|保持不变|被置空/无效|
|何时调用|拷贝左值|移动右值|

### 为什么移动构造要加 `noexcept`

cpp

Buffer(Buffer&& other) noexcept
//                      ^^^^^^^^

`noexcept` 告诉编译器「这个函数不会抛异常」。这对移动构造特别重要，因为：

**标准库容器在扩容时，会优先选择移动而非拷贝——但前提是移动构造是 `noexcept` 的。**

比如 `std::vector` 扩容：

cpp

std::vector<Buffer> vec;
vec.push_back(Buffer(1000000));   // 触发扩容

扩容时，`vector` 需要把旧元素搬到新内存。如果 `Buffer` 的移动构造是 `noexcept`，`vector` 会用移动（快）；如果移动构造可能抛异常，`vector` 会退回用拷贝（慢），因为要保证「强异常安全」——万一移动中途抛异常，源对象已经被改坏，无法恢复。

所以**移动构造几乎总是应该标 `noexcept`**。

### 移动赋值

和移动构造配套的还有**移动赋值运算符**：

cpp

Buffer& operator=(Buffer&& other) noexcept {
    if (this != &other) {
        delete[] data_;          // 释放自己原有的资源
        data_ = other.data_;     // 偷对方的
        size_ = other.size_;
        other.data_ = nullptr;   // 置空对方
        other.size_ = 0;
    }
    return *this;
}

区别：

||移动构造|移动赋值|
|---|---|---|
|作用|创建新对象时转移资源|已有对象被赋值时转移资源|
|是否需要释放原有资源|不需要（新对象还没资源）|需要（先释放自己的）|
|自赋值检查|不需要|需要（`this != &other`）|

### 和拷贝构造的关系：Rule of Five

C++ 里有几个相关规则：

**Rule of Three（C++11 前）**  
如果需要自定义析构、拷贝构造、拷贝赋值中的任何一个，通常三个都要定义。

**Rule of Five（C++11 起）**  
加上移动构造和移动赋值，一共五个：

cpp

class Buffer {
public:
    ~Buffer();                              // 1. 析构
    Buffer(const Buffer&);                  // 2. 拷贝构造
    Buffer& operator=(const Buffer&);       // 3. 拷贝赋值
    Buffer(Buffer&&) noexcept;              // 4. 移动构造
    Buffer& operator=(Buffer&&) noexcept;   // 5. 移动赋值
};

**Rule of Zero**  
更好的做法：如果类内部用 `std::vector`、`std::string`、`std::unique_ptr` 这些已经管理好资源的成员，就**一个都不用写**，编译器自动生成的版本就正确。

cpp

class Buffer {
    std::vector<int> data_;   // 自动支持拷贝和移动
};
// 不需要写析构、拷贝、移动

### 回到 SocketCan 的例子

你之前看的 `SocketCan` 类：

cpp

class SocketCan final {
public:
    SocketCan() = default;
    SocketCan(const SocketCan&) = delete;             // 禁止拷贝
    SocketCan& operator=(const SocketCan&) = delete;  // 禁止拷贝赋值
};

它禁止了拷贝，因为内部管理 socket fd（不可复制）。但**没有提供移动构造**，这意味着：

cpp

SocketCan createSocket() {
    SocketCan s("can0");
    return s;   // 不能移动，只能拷贝——但拷贝被禁了
}                // 编译错误！

所以这个类目前**无法从函数返回**，也**无法放入容器**（`std::vector<SocketCan>` 会失败，因为容器需要移动或拷贝）。正确的做法是补上移动构造和移动赋值：

cpp

SocketCan(SocketCan&& other) noexcept
    : fd_(other.fd_) {
    other.fd_ = -1;   // 转移所有权
}
SocketCan& operator=(SocketCan&& other) noexcept {
    if (this != &other) {
        close();          // 释放自己的 fd
        fd_ = other.fd_;
        other.fd_ = -1;
    }
    return *this;
}

这样 `SocketCan` 就能安全地转移所有权，同时避免 fd 被重复关闭。

### 一句话总结

**移动构造是 C++11 的机制，用 `T&&` 参数把源对象的资源「偷」过来，而不是复制。它把 O(n) 的拷贝变成 O(1) 的指针转移，适用于临时对象和 `std::move` 的场景。移动构造应标 `noexcept`，这样标准库容器扩容时才会优先用它。管理资源的类（如 SocketCan）通常禁止拷贝、提供移动，才能安全地在函数返回和容器中使用。**
