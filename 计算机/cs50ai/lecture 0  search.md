## 1. 什么是搜索问题

搜索（Search）不是指在数据库里查关键词，而是：

> 已知初始状态和目标条件，寻找一串动作，使智能体从初始状态到达目标状态。

典型例子包括地图导航、迷宫、十五数码、井字棋和国际象棋。

### 1.1 基本术语

|概念|含义|导航例子|
|---|---|---|
|Agent|感知环境并采取行动的实体|汽车/导航程序|
|State `s`|对当前局面的完整描述|汽车当前位置|
|Initial State|搜索开始时的状态|起点|
|`Actions(s)`|状态 `s` 下所有合法动作|可驶入的相邻道路|
|`Result(s, a)`|在 `s` 执行 `a` 后得到的新状态|沿道路到达下一个路口|
|State Space|从初始状态经动作可达的全部状态|整张可达路网|
|Goal Test|判断状态是否满足目标|是否到达目的地|
|Path Cost|一条路径的累计代价|距离、时间、能耗或风险|
$[$  
$s_0 \xrightarrow{a_1} s_1 \xrightarrow{a_2} \cdots \xrightarrow{a_k} s_g$  
$]$

- **解（solution）**：从初始状态到目标状态的一串动作。
    
- **最优解（optimal solution）**：所有解中路径代价最低的解。




## 3. 通用图搜索框架

两个核心容器：

- **Frontier（边界/开放集合）**：已经发现但尚未展开的节点。
    
- **Explored Set（已探索集合）**：已经展开的状态，用于避免绕圈和重复搜索。
    

### 3.1 通用流程

```
frontier ← 只包含初始节点
explored ← 空集合

循环：
    如果 frontier 为空：
        返回“无解”

    按搜索策略从 frontier 取出一个 node

    如果 node.state 满足目标测试：
        沿 parent 回溯并返回解

    将 node.state 加入 explored

    对 Actions(node.state) 中的每个 action：
        child_state ← Result(node.state, action)
        如果 child_state 不在 explored，且不在 frontier：
            构造 child_node 并加入 frontier
```

搜索算法之间的核心差别通常只有一个：**下一步从 frontier 取哪个节点？**

### 4.1 深度优先搜索 DFS

Frontier 使用栈（Stack），规则为 **LIFO：后进先出**。

直觉：沿一条路不断深入，走不通后再回退尝试其他分支。

```
node = frontier[-1]
frontier = frontier[:-1]
```

特点：

- 可能很快碰巧找到解；
    
- 内存需求通常小于 BFS；
    
- 找到的第一个解不保证最优；
    
- 在无限深状态空间中可能一直沿错误分支深入，因此甚至不完备；在有限图搜索且正确去重时可以找到存在的解。
    

### 4.2 广度优先搜索 BFS

Frontier 使用队列（Queue），规则为 **FIFO：先进先出**。

直觉：先检查距离起点 1 步的全部状态，再检查 2 步、3 步……

```
node = frontier[0]
frontier = frontier[1:]
```

特点：

- 在分支有限时是完备的；
    
- 当每一步代价相同，BFS 找到的第一个解具有最少步数，因此是最优解；
    
- 若道路代价不同，最少步数不一定等于最低总代价，此时不能直接声称 BFS 最优；
    
- 通常需要保存整层节点，内存消耗较大。
    

### 4.3 DFS 与 BFS 对比

|算法|Frontier|扩展方式|完备性|最优性|主要问题|
|---|---|---|---|---|---|
|DFS|栈 LIFO|一条路先走到底|有限图中通常是|否|容易走入很深的错误分支|
|BFS|队列 FIFO|一层一层搜索|是（有限分支）|等步长时是|内存消耗大|

若分支因子为 `b`，最浅解深度为 `d`，BFS 的时间和空间量级都可能达到 `O(b^d)`。这说明状态空间会随深度指数膨胀。

## 5. 有信息搜索与启发式函数

有信息搜索（informed search）利用问题相关知识判断哪个节点更有希望。

### 5.1 启发式函数 `h(n)`

[  
h(n) \approx \text{从节点 } n \text{ 到目标的剩余代价}  
]

例如网格中可使用曼哈顿距离：

[  
h(n)=|x_n-x_g|+|y_n-y_g|  
]

它忽略墙壁，只估计横向与纵向至少要走多少格，所以计算快，但不一定等于真实距离。



## 6. Greedy Best-First Search

贪心最佳优先搜索每次展开 `h(n)` 最小的节点：

[  
f(n)=h(n)  
]

它只问：**从当前节点看，谁似乎离目标最近？**

优点：好的启发式往往能显著减少搜索节点。  
缺点：忽略已经付出的代价，可能被障碍物或坏启发式误导；通常不保证最优。

## 7. A* 搜索

A* 同时考虑：

- `g(n)`：从起点到当前节点的实际累计代价；
    
- `h(n)`：从当前节点到目标的估计剩余代价。
    

[  
f(n)=g(n)+h(n)  
]

直觉：

> 不只看“现在离目标多近”，还要看“为了来到这里已经付出了多少”。


### 7.1 A* 最优的条件

启发式通常需要满足：

1. **可采纳（admissible）**：永不高估真实最低剩余代价。
    

[  
0 \le h(n) \le h^*(n)  
]

2. **一致（consistent）**：对任意后继节点 `n'` 和步代价 `c(n,n')`：
    

[  
h(n) \le c(n,n')+h(n')  
]

一致性相当于启发式满足三角不等式，它保证沿路径的 `f` 值不会下降。图搜索版本的 A* 在一致启发式下可以在节点出队时安全地将其关闭。

几个重要特例：

- `h(n)=0` 时，A* 退化为按累计代价扩展的统一代价搜索思想；
    
- 如果只看 `h(n)`、忽略 `g(n)`，就变成 Greedy Best-First Search；
    
- 启发式越接近真实代价但仍不过估，通常展开的节点越少。
    

### 7.2 搜索算法总表

| 算法     | 选择依据           | 使用目标信息 | 一般是否最优   |
| ------ | -------------- | ------ | -------- |
| DFS    | 最后加入的节点        | 否      | 否        |
| BFS    | 最早加入的节点        | 否      | 等步长时是    |
| Greedy | 最小 `h(n)`      | 是      | 否        |
| A*     | 最小 `g(n)+h(n)` | 是      | 满足相应条件时是 |


## 8. 对抗搜索

此前的搜索面对的是静态环境；对抗搜索（adversarial search）中存在对手，对手会主动选择对自己有利、对你不利的动作。典型应用是井字棋、国际象棋等双人零和博弈。

### 8.1 博弈问题的形式化

以井字棋为例：

|函数|含义|
|---|---|
|`S₀`|初始棋盘|
|`Player(s)`|当前轮到谁|
|`Actions(s)`|当前所有合法落子位置|
|`Result(s, a)`|落子后的棋盘|
|`Terminal(s)`|游戏是否结束|
|`Utility(s)`|终局收益，例如胜 `+1`、平 `0`、负 `-1`|

## 9. Minimax

假设双方都采取最优策略：

- **MAX** 希望最终效用最大；
    
- **MIN** 希望最终效用最小。
    

状态价值递归定义为：

[  
V(s)=  
\begin{cases}  
Utility(s), & s \text{ 为终局} \  
\max_{a \in Actions(s)} V(Result(s,a)), & MAX\text{ 回合} \  
\min_{a \in Actions(s)} V(Result(s,a)), & MIN\text{ 回合}  
\end{cases}  
]

伪代码：

```
Max-Value(state):
    if Terminal(state): return Utility(state)
    v = -∞
    for action in Actions(state):
        v = max(v, Min-Value(Result(state, action)))
    return v

Min-Value(state):
    if Terminal(state): return Utility(state)
    v = +∞
    for action in Actions(state):
        v = min(v, Max-Value(Result(state, action)))
    return v
```

关键不是“预测对方可能随便怎么走”，而是问：

> 如果对方也足够聪明，并总选择让我最难受的动作，我现在应该选什么？

## 10. Alpha-Beta Pruning

Alpha-Beta 剪枝不会改变 Minimax 的最终答案，只跳过不可能影响决策的分支。

- `α`：MAX 当前已知至少能得到的最好值；
    
- `β`：MIN 当前已知至多会允许的最好值；
    
- 当 `α ≥ β` 时，剩余分支可以剪掉。
    

直觉例子：MAX 已有一个保证得分为 4 的选择。考察另一个选择时，发现 MIN 已能把结果压到 3。无论该分支其他叶子多好，MIN 都可以选 3，因此 MAX 不会选择这一整条分支，继续计算没有意义。

剪枝效率强烈依赖动作检查顺序：越早检查到好动作，越容易剪掉更多分支。

## 11. Depth-Limited Minimax 与评估函数

完整 Minimax 必须一直搜索到终局，但象棋等游戏的博弈树极大，无法穷举。

解决办法：

1. 只向前搜索固定层数；
    
2. 到达深度上限后，不再等待真正终局；
    
3. 用评估函数 `Eval(s)` 估计当前局面对 MAX 有多有利。
    

例如象棋评估可综合棋子价值、位置、王的安全性和行动空间。评估函数越准确，深度受限 Minimax 的决策通常越好。
