**静态网页**，简单来说，就是**服务器直接把一个已经写好的文件原样发给浏览器，浏览器拿到什么就显示什么**。

它和你之前问的 Nginx 关系很密切——Nginx 最基础、最擅长的功能之一，就是高效地托管静态网页。

### 核心特点

**1. 内容是“预先写好”的**  
网页的 HTML、CSS、JavaScript、图片等文件，在用户访问之前就已经存在于服务器上了。用户请求哪个文件，服务器就把哪个文件发回去。

**2. 每个用户看到的内容都一样**  
除非用 JavaScript 在浏览器端动态改，否则 A 用户和 B 用户访问同一个 URL，拿到的 HTML 文件是完全相同的。服务器端不会为不同用户生成不同内容。

**3. 不需要后端程序参与**  
服务器不需要运行 PHP、Java、Python、Node.js 等程序来处理请求。Nginx 或 Apache 直接读文件、发文件，就这么简单。

### 静态网页 vs 动态网页

|对比项|静态网页|动态网页|
|---|---|---|
|内容来源|预先写好的文件|服务器程序实时生成|
|是否依赖后端|不依赖|依赖（PHP/Java/Python 等）|
|不同用户看到的内容|通常相同|可以不同（如登录后的个人主页）|
|访问速度|很快|相对较慢（要执行程序、查数据库）|
|服务器压力|很小|较大|
|典型文件|`.html`、`.css`、`.js`、图片|`.php`、`.jsp`、`.asp` 等|
|适合场景|博客、文档、企业官网、产品介绍页|电商、社交、后台系统|

### 静态网页不“死板”

很多人以为静态网页就是“不能交互、一成不变”，其实不完全对。静态网页里可以包含 JavaScript，在浏览器端实现很多动态效果，比如：

- 点击按钮弹出菜单
    
- 表单校验
    
- 通过 AJAX 请求后端 API 获取数据并更新页面
    
- 前端框架（Vue、React）构建的单页应用
    

这种情况下，HTML 文件本身是静态的，但页面在浏览器里跑起来后可以很“动态”。这类网站常被称为 **静态站点** 或 **前后端分离** 的架构。

### 静态网页的优势

- **快**：没有后端计算和数据库查询，直接发文件
    
- **稳**：没有程序逻辑，不容易因为代码 bug 或数据库故障而崩溃
    
- **省**：服务器配置要求低，Nginx 就能轻松扛住高并发
    
- **安全**：没有后端程序，攻击面小
    
- **易部署**：文件拷过去就能用，可以放在 CDN 上全球加速
    

### 常见静态网页托管方式

- **Nginx / Apache**：传统方式，自己搭服务器
    
- **对象存储 + CDN**：如阿里云 OSS、腾讯云 COS、AWS S3
    
- **静态托管平台**：GitHub Pages、Vercel、Netlify、Cloudflare Pages
    

### 什么时候该用静态网页？

适合：内容不常变、不需要用户登录、不需要个性化推荐、以展示为主的页面。

不适合：需要用户系统、实时数据、复杂业务逻辑的场景——这些通常要用动态网页或前后端分离架构。

总结一句话：**静态网页就是“服务器发什么，浏览器显示什么”，简单、快、稳，是 Web 世界最基础的形态。**
